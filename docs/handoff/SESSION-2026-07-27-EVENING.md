## 本場的方法論教訓

**推測會付出版本代價。** #11 從 beta7 修到 beta10 才對，中間 beta8 的幾何修正是我在沒有決定性證據時先動手，beta9 的「撐回去」則是誤判 resizeTo 一定成功。真正解出來是靠三份實機診斷：viewport 197x327／254x269 全失敗、700x453 全成功、以及 resize 事件連續三次 clamp。

**代價可控的原因是先補了儀器。** beta5／beta6 是純診斷版（worker 診斷落盤、報告流程補上 RuntimeDiagnostics）。在那之前使用者匯出的診斷 summary 完全沒有 blocking 與 report，什麼都查不到。

**下次遇到同類問題的順序**：先確認診斷拿得到 → 讓失敗誠實地記錄原因 → 再依原因分佈決定改哪裡。不要在只有症狀時就改判定邏輯。
